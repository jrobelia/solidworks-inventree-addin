2. `BomCompareReadinessCheck` extraction (BOM Compare pre-flight)

## M3 QA Plan — SolidWorks In-App Verification

### Setup
Open a part document that has a known IPN linked to an InvenTree part. Have a second InvenTree server config ready to test the stale-data scenario.

---

### 1 — Task Pane State Machine

| # | Action | Expected |
|---|--------|----------|
| 1.1 | Open SolidWorks with no document | Task pane shows EMPTY state, no fields visible |
| 1.2 | Open a part with no IPN property | Task pane shows UNLINKED, Fetch disabled |
| 1.3 | Type an IPN into the SW custom property | Task pane transitions to LINKED, Fetch button enabled |
| 1.4 | Click Fetch | Task pane transitions to POPULATED, all preview fields filled |
| 1.5 | Close the document | Task pane returns to EMPTY, all fields cleared |

---

### 2 — Fetch and Apply (PartSyncSession wiring — highest risk area)

| # | Action | Expected |
|---|--------|----------|
| 2.1 | Fetch a part | Name, Notes, Description, Revision, PK, thumbnail, InStock, Ordering, Active all display correctly |
| 2.2 | Click "Apply to SW Doc" (all fields) | All mapped SW custom properties updated; match indicators turn green |
| 2.3 | Click Apply Name only | Only the Name property updated in SW |
| 2.4 | Click Apply Notes only | Only Notes updated |
| 2.5 | Click Apply Description only | Only Description updated |
| 2.6 | Click Apply PK only | Only InvenTree PK property updated |
| 2.7 | Apply a field where the SW property doesn't exist yet | Dialog warns about missing property; user confirms → property created and written |
